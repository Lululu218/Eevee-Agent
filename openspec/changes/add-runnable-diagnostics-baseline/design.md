## Context

现有工作台沿用 Vue 登录入口，后端用户数据和会话分别依赖 MySQL、Redis。Spring 启动时会装配 Milvus 客户端并初始化意图缓存，首页还会请求推荐问题。仅隐藏知识库菜单仍可能导致后端无法启动，或登录后首页发出无效请求。[Milvus 客户端](../../../main-application/src/main/java/com/azheng/boot/rag/core/embedding/milvus/config/MilvusClientConfig.java) · [意图初始化](../../../main-application/src/main/java/com/azheng/boot/rag/core/intent/DefaultIntentClassifier.java) · [工作台首页](../../../frontend/src/components/Home.vue)

## Goals / Non-Goals

M1 把“登录并读取报告”与“调用模型和知识检索”分开，使同一份 XML 在每次演示中都能定位到同一个失败测试。报告读取复用登录会话。模型解释、知识引用、任务持久化和工单写入按[首版里程碑](../../../resources/markdown/Eevee-Agent自托管工作台首版方案.md#里程碑与交付证据)推进。

## Decisions

1. **用一个后端配置项切换知识库。** 拟采用 `eevee.knowledge.enabled`，默认启用。关闭时，沿着注入关系一起隔离 Milvus、知识库对象存储、知识检索和依赖它们的初始化逻辑。保留供登录使用的基础组件。工作台从后端获知知识库状态，再决定是否加载推荐问题等入口。前后端各设一个独立开关容易出现显示状态与服务状态不一致。
2. **注册一个随仓库分发的只读示例。** 服务端将稳定的工作区标识映射到公开样例，并明确授予登录用户该示例的读取权限。浏览器提交工作区与报告标识。后端先校验访问权，再在登记目录内解析已列入清单的文件，核对实际路径仍位于目录内。这样可复用原有登录，首期也无需为单个公开样例建立项目管理表。
3. **通过独立的报告读取入口返回 XML 事实。** 后端提取 Surefire 的测试类、方法、`failure` 或 `error` 类型与可用消息，并返回工作区内的相对来源。XML 解析禁用外部实体和外部资源加载。Vue 直接展示结果，区分报告缺失、解析失败和有效报告。直接复用聊天问答链会把固定输入的展示结果绑定到模型或检索服务。
4. **将故意失败的 Maven 样例独立于默认构建。** 仓库保存样例源码、预生成报告及其预期类名、方法名和异常类型。报告放在受版本控制的样例目录，避开通常被忽略的 `target/`。开发者按样例说明手动重新运行测试，以稳定字段核对结果，允许耗时和本机路径变化。

## Risks / Trade-offs

- 启动时仍可能有组件间接创建知识库客户端 → 在 Milvus 和对象存储均未运行时，从干净检出经过浏览器登录并读取报告，再在启用模式回归原问答入口。
- 项目现有建表脚本含删表语句 → 本地演示使用独立的空 MySQL 库和明确的登录准备步骤，启动流程不得自动重置共享库。[已有建表脚本](../../../resources/database/schema.sql)
- 公共样例会掩盖越权请求的问题 → 对匿名用户、未获授权的工作区和超出登记范围的报告分别验证拒绝结果，检查响应是否泄露文件内容或绝对路径。

## Migration Plan

按新增配置、可选报告入口和独立样例交付。原有部署沿用默认启用设置，本地演示显式选择关闭。验收时分别记录两种模式的依赖与结果。若关闭模式的装配出现问题，可恢复启用设置并重启验证原登录及问答入口。M1 设计无需迁移现有会话或业务表。
